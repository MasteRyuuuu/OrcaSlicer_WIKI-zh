# 编译器缓存

编译器缓存会保留每次编译生成的目标文件，并以源文件、它引入的头文件和命令行的哈希值为键保存。当这些输入再次出现时，直接把目标文件复制回来，而不是重新编译。这样一来，切换分支后、重新配置后，或者在新的编译目录中重新编译，只需要平时的一小部分时间。

OrcaSlicer 在 Windows、Linux 和 macOS 上都支持 [ccache]({{L1}}) 和 [sccache]({{L2}})。

{{T1}}

## 代价

缓存不是免费的，是否划算取决于你的工作方式。

只有当请求的内容已经在缓存中时，缓存才会起作用，所以任何东西的第一次编译只是在填充缓存，没有任何收益。在 Windows 上，两种工具都不会缓存使用预编译头的编译，所以在那里启用缓存就意味着不使用预编译头编译。这会让每次编译都自己解析全部头文件，从零开始的编译时间大约会翻倍。在 Linux 和 macOS 上，编译脚本会把 ccache 设置为能够缓存这类编译，所以预编译头保持开启。

你得到的回报在于重新编译。已经在缓存中的配置只需要链接而不需要编译，同样的工作量从几十分钟降到一分钟左右，其中大部分时间是链接。

这种取舍更适合某些工作习惯：

- **值得**：你经常切换分支、维护不止一个编译目录、经常重新配置，或者以不同配置重新编译同一个提交。
- **意义不大**：你只编译一个目录，修改少数几个文件后增量编译。Ninja 本来就会跳过你没有改动的所有内容，而预编译头会让你改动过的文件编译得更快。

缓存同时适用于默认的 Xcode 生成器（通过 Xcode 的 Compiler Launcher 设置）和 Ninja（`-x`）。与 Linux 一样，脚本会把 ccache 设置为能够缓存使用预编译头的编译，所以预编译头保持开启。

## 缓存大小

缓存满了之后，两种工具都会淘汰最久未使用的内容，所以上限设得太小会丢弃你仍然需要的编译结果。ccache 默认上限为 5 GB，而 OrcaSlicer 的一次完整编译会占用其中的 1 到 2 GB，所以请按你想保留的编译数量大致提高上限：

{{C8}}

这里的"一次编译"指一个检出目录的一种配置。Debug 和 Release 分别计算，另一个工作树中的同一提交也单独计算。

- **5 GB**（默认）可以保留两到三次。只用一种配置时足够了。
- **20 GB** 可以涵盖多种配置和多个分支，适合大多数工作。
- **50 GB** 或更多：如果你维护多个工作树，或者经常在 Debug 和 Release 之间切换。

这一部分只适用于 ccache；sccache 没有对应的设置。

> [!NOTE]
> 开启它会改变每一条编译命令，所以开启后的第一次编译会重新编译全部内容，并重新填充缓存。

## 检查是否生效

{{C10}}

`Cacheable calls` 是 ccache 看到的编译次数，`Hits` 是它无需编译就直接提供结果的次数。第一次编译大多是未命中。把同一个提交编译到一个新目录中，这些文件应当会作为命中返回，并且几乎全部是直接命中。

如果 `Uncacheable calls` 达到数百次，说明有什么东西阻止了 ccache 保存它看到的大部分编译。`ccache -sv` 会列出每次的原因。常见的原因是仍在使用预编译头，另一个原因是 `cl.exe` 编译中带有 `/Zi`。
