# 页面

`orca.pages` 让插件可以在**主窗口中添加自己的选项卡**，位于 OrcaSlicer 内置选项卡（准备、预览、设备……）旁边。该选项卡承载由插件提供的 HTML 页面。继承 `orca.pages.PagesPluginCapabilityBase`；它的 `get_type()` 返回 `Pages`。

| 方法 | 是否必需 | 用途 |
|---|---|---|
| `get_name()` | 是 | 选项卡标签 |
| `get_ui()` | 是 | 以字符串形式返回页面的 HTML |
| `get_icon()` | 否 | 返回 `.svg` / `.png` 选项卡图标的路径；为空（默认）表示没有图标 |
| `on_message(data)` | 否 | 接收页面发出的每个 `orca.postMessage(obj)`，已从 JSON 解码 |
| `post_message(data)` | 已提供 | 把一个可序列化为 JSON 的值发送给页面的 `orca.onMessage` 处理函数 |

## 行为

- 功能加载并启用时添加选项卡，功能被禁用或其插件被卸载时移除选项卡。页面本身在选项卡第一次显示时才构建，所以在此之前不会调用 `get_ui()`。
- 页面会得到一个 `window.orca` 桥接对象，其中有 `orca.postMessage(obj)` 和 `orca.onMessage(cb)`（没有 `submit()` 或 `close()`）。它的主题样式与[宿主 UI]({{L1}}) 对话框相同；如果用户重新加载页面，插件的 HTML 会再次加载，所以请把权威状态保存在插件中，让页面在加载时向插件索取。
- 在页面构建之前调用的 `post_message()` 会被丢弃；上面的模式（页面在加载时索取数据）可以避免这一问题。
- 本来会打开新窗口的链接，会直接在页面中加载。
- 如果 `get_ui()` 抛出异常，错误会被记录到日志，选项卡保持为空。
- 并排显示的插件选项卡数量在**偏好设置 > 常规 > 插件 > 可见插件页数**中设置（1-10，默认 5）。更多的页面会收进最后一个插件选项卡上的下拉菜单中。

关于注册以及每项功能都会继承的成员，请参见[注册]({{L2}})。
