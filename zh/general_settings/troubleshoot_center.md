# 故障排查中心

**故障排查中心**把诊断问题所需的一切——也是你提交错误报告时维护者会向你要的一切——集中到一个对话框中：系统信息、应用程序日志、配置文件夹，以及已加载配置的概览。

它不会收集或分享任何用户特定的信息。对话框生成的所有内容都写入你选择的位置，除非你自己把它附加到报告中，否则不会有任何东西离开你的电脑。

{{T1}}

## 打开故障排查中心

有两种打开方式：

- **帮助菜单** → **故障排查中心**。
- 启用[开发者模式]({{L1}})时的**模式选择器**。在开发者模式下，选择器被锁定（没有可切换的模式），因此单击它会改为打开故障排查中心。它的提示文字为*开发者模式——启动故障排查中心...*。

> [!NOTE]
> 只有侧边栏上的模式选择器能打开这个对话框。  
> 打印机设置和耗材丝设置对话框中显示的模式选择器不会打开它。

## 系统信息

对话框左侧的面板列出了重现问题时最常需要的数据：

- 操作系统及其版本
- **安装包类型**——OrcaSlicer 的安装方式：Windows 上为 *Local Build*（本地编译）、*Installed*（安装版）或 *Portable*（便携版），Linux 上为 *AppImage* 或 *Flatpak*，macOS 上为 *Homebrew*
- CPU
- 已安装的内存
- GPU
- 显示器，以及它们的原生分辨率和缩放比例

面板上方显示应用程序版本和编译哈希，后者链接到该版本编译所用的确切提交。

有两个按钮控制这个面板：

- **复制**——把整块信息复制到剪贴板，格式已经适合直接粘贴到 GitHub 报告中。
- **隐藏** / **显示**——把面板折叠到只显示操作系统名称。如果你不想展示完整的配置信息，可以在给对话框截图之前使用它。

## 信息

- **打包...**——把当前项目文件和当前会话的日志收集到一个名为 `OrcaSlicer_PackedDebugInfo_<YYYYMMDD_HHMM>.zip` 的 ZIP 文件中。这就是要附加到错误报告中的文件。
    - 如果项目有未保存的更改，会先要求你保存。选择**否**会关闭对话框，以便你检查项目。
    - 如果当前会话中没有保存过项目，则只打包日志。
- **报告问题**——打开 GitHub 错误报告表单，操作系统、OrcaSlicer 版本和系统版本字段都已预先填好。

> [!TIP]
> 额外的可视示例——图片或简短的屏幕录制——能让报告更容易处理。把它们和打包的 ZIP 一起附上。

## 配置文件

- **清理系统配置缓存** → **清理**——删除配置文件夹中缓存的 `system` 文件夹，使系统配置在下次启动时从头重建。当更新后配置看起来损坏或过时时很有用。

    > [!WARNING]
    > 此操作需要重启。删除文件夹后 OrcaSlicer 会关闭并自行重新启动，所以请确保没有其他 OrcaSlicer 实例在运行，并且项目已经保存。如果文件夹中有任何文件被其他应用程序锁定，操作会中止，不会删除任何内容。

- **已加载配置概览** → **导出...**——把已加载配置的详细概览（包括兼容性元数据）写入你选择的 `ProfilesOverview.json` 文件。
- 下方的表格针对**打印机**、**耗材丝**和**工艺**，显示当前正在使用的配置数量，后面依次是系统配置和用户配置的数量（`使用中 / 系统 + 用户`）。

关于这些配置是什么、存放在哪里，请参见[用户配置]({{L2}})。

## 详情

- **配置文件夹** → **浏览...**——在文件管理器中打开 OrcaSlicer 数据目录。配置、应用程序设置和日志都存放在这里：
    - Windows：`%APPDATA%\OrcaSlicer`
    - macOS：`~/Library/Application Support/OrcaSlicer`
    - Linux：`~/.config/OrcaSlicer`
- **日志级别**——设置日志文件的详细程度：`fatal`、`error`、`warning`、`info`、`debug` 或 `trace`。更改立即生效，并在重启后保留。

    > [!TIP]
    > 当被要求提供更详细的信息来重现错误时，把级别设为 `debug` 或 `trace`，重启 OrcaSlicer，重现问题，然后打包日志。之后再把级别调低——详细日志会产生很大的文件。

- **已存储的日志** → **打包...**——把所有已存储的日志文件导出为 `OrcaSlicer_Logs_<YYYYMMDD_HHMM>.zip`。
- **已存储的日志** → **清除**——删除已存储的日志文件，只保留当前会话的日志。按钮旁边的标签会显示已存储了多少个日志文件、占用了多少空间。

## 报告问题

一份好的报告通常包含：

1. 从[系统信息]({{L3}})面板中用**复制**得到的内容。
2. 在[信息]({{L4}})部分用**打包...**生成的 ZIP——包含项目和会话日志。
3. 重现问题的步骤；如果是视觉上的问题，再附上截图或屏幕录制。

然后使用**报告问题**打开预先填好的错误报告，并附上这些文件。
